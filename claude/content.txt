# PROTOS PROJECT STRUCTURE

## Data Storage Overview
Protos uses three distinct data storage locations:
- **reference_data/** (in src/protos/): Immutable reference datasets shipped with the library
- **test-data/** (in tests/): Test fixtures that mimic real data structure for unit tests  
- **data/** (project root): Production data directory for actual analyses and CLI operations

## Key Components

### Processors (all inherit from BaseProcessor)
- **GRNBaseProcessor**: Handles Generic Residue Numbering data
- **CifBaseProcessor**: Processes 3D structure data (PDB/mmCIF files)  
- **SeqProcessor**: Manages sequence data and alignments
- **PropertyProcessor**: Handles metadata and properties

### CLI Tools (in src/protos/cli/grn/)
All updated to use GRNBaseProcessor and support:
- Dataset IDs or file paths (via --use-file flag)
- Custom data root (via --data-root argument)
- Both dot notation (3.50) and x notation (3x50) for GRNs

### GRN System
- **Notation**: Dot notation (1.50, 2.50) is now standard; x notation (1x50, 2x50) is deprecated
- **Key positions**: x.50 in each helix (most conserved)
- **7.50**: Schiff base lysine in opsins (critical for function)
- **Protein families**: microbial_opsins, gpcr_a, iLBP

### Recent Updates (2025-06-25)
- All CLI scripts migrated to GRNBaseProcessor
- Added GRN-Structure integration methods to CifBaseProcessor
- Fixed path handling and notation compatibility
- Created comprehensive test suite with real data
- Added workaround for BaseProcessor subdirectory bug

### Current Issues
- BaseProcessor returns file path instead of data for subdirectory datasets (workaround in place)
- GRN parser internally expects x notation while data uses dot notation
- Need better test sequences for GRN assignment demonstration

### GRN Assignment Process
1. Load reference GRN table
2. Find best matching reference sequence (MMseqs2)
3. Perform pairwise alignment (BLOSUM62)
4. Transfer GRN numbers through alignment
5. Apply boundary constraints
6. Output annotated sequences
